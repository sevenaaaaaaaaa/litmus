# P1-02 · 灵魂卡三入口

> 看板 DoD：三入口共用一份确认 UI；跳过时生成「临时卡」并标注「未确认」。

## 三条铁律（这轮的全部设计）

1. **候选必须逐字有出处。** 候选文字必须是用户原话或旧文里的原句，程序会校验"是子串"，编造直接报错。
2. **三个入口共用同一份确认与落盘。** 访谈 / 提炼 / 粘贴只在"候选从哪来"上不同，之后的接受 / 改写 / 删除、区块顺序、锚点生成、frontmatter 全部同一条路径。
3. **跳过也能用。** 生成临时卡（`confirmed: false`），每个候选带 `provenance`，AI 输出据此标「未确认」。

## 三个入口

| 入口 | 输入 | 候选来自 | 出处长什么样 |
|---|---|---|---|
| **访谈** | 六问的回答（可用语音转写） | 用户每句话本身 | `answer:belief` |
| **提炼** | 库里已有的笔记 | 带线索词的句子 | `Notes/note-1.md:3` |
| **粘贴** | 自我介绍 / 旧文章 / 主页 | 切句后的原句 | `paste:voice` |

**提炼不做生成**：只按线索词（"不是 / 先看 / 不写 / 短句 / 如何 / 读者"）挑句子，标题、代码块、列表、链接、网址一律不进候选。规则可读、可测、不要钱；以后可以换成 embedding，但现在不需要。

## 共用流程

```
candidates → newReview → decide(accepted | edited | dropped) → assemble → parseSoul 校验 → writeCard（原子写）
```

- **改写**允许改字，但必须仍能指回原句（`provenance` 不丢），且空白改写直接报错。
- **落盘前先自检**：`assemble` 生成的 Markdown 必须能被 P1-01 的解析器读成 0 错误；读不出来就不写盘。
- **原子写**：写 `.tmp-<pid>` 再 rename；失败不留半个文件。
- **不覆盖**：已有灵魂卡时抛错，除非显式 `force`。

## 实跑

```
$ node p1-02-soul-entrances/demo.mjs
访谈 3 条 / 提炼 6 条 / 粘贴 2 条
三个入口的候选都逐字可核：true
待确认 0 条
落盘前解析：10 条 / 10 锚点 / 错误 0 条
写入：Notes/灵魂卡.md　临时卡=false
跳过路径：临时卡 6 条 / confirmed=false / 出处 6 条
```

`node --test p1-02-soul-entrances/entrances.test.mjs` → **12/12**。

## 边界

- **没有 UI**：只有候选结构、确认流程、落盘格式。UI 由 P1-03 的动作规格驱动。
- **线索词是硬编码**：六个区块各一组，写在 `CUES` 里。
- **改写不留原文**：卡片里只有改写后的句子；原句只存在于 `provenance` 的内存结构里，没有持久化。
- **没有去重**：同一句话可能从两个入口各来一次。

## 新思路

1. **"只挑句子"解决了编造，没解决"半句话"。** 用户口头说的常是半句、带"那个"的口语；直接落盘很难看。需要"轻改写"，但改写后必须仍指回原句——现在 `provenance` 只在内存里，得持久化才能支撑这条。
2. **线索词表应该可编辑。** 硬编码的 `CUES` 现在能解释、能测试，但用户不能加词。把词表变成 `soul-rules.json` 更合适：用户加一个词，提炼立刻变准，不用改代码。
3. **临时卡要说明"它缺什么"。** 只标「未确认」不够；用户不知道为什么"不像我"。应该列出"这张卡只有 2 个区块有内容，AI 读到的东西会变窄"。
4. **三入口应该由"用户手头有什么"决定，不由我们推荐。** 有话 → 访谈；有旧文 → 提炼；只有主页 → 粘贴。现在默认推荐访谈，会让没准备的人卡住。
5. **去重是必须的。** 同一句话从访谈和提炼各来一次，会生成两个锚点、两条一样的判断。去重键应该是去掉空白后的文本哈希，且要告诉用户"这条重复了，已合并"。

## 对后续的影响

- **P1-10 临时卡升级**：升级动作就是把这些 `provenance` 覆盖的条目从 `confirmed:false` 翻成 true，并保留锚点——现在缺的是"哪些条目是 AI 推断"的粒度标记。
- **P1-05**：三入口产出的卡走同一条落盘路径，正好可以复用后端的 `commit`。
