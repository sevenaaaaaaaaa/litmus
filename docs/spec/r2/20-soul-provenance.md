# P1-12 · 临时卡的出处（provenance）落盘

状态：done（模型层 + 参考实现；产品侧落盘随 P1-10b 的端点）
建立：2026-11-24
前置：[P1-01 灵魂卡数据模型](11-soul-model.md) · [P1-02 灵魂卡三入口](12-soul-entrances.md) · [P1-10a 模型进内核](19-soul-in-kernel.md)

## 为什么先做这一步

P1-02 的临时卡确实带出处，但那句话是这么来的：

```js
return { markdown: assemble(review, { confirmed: false }),
         provenance: cands.map((c) => ({ block: c.block, ref: c.provenance.ref })) };
```

出处是**和 markdown 并列的返回值**。卡文件里一个字都没有。也就是说：卡一写盘，出处就没了。

三件事让它不能等：

1. **ref 会漂**。`Notes/note-1.md:7` 是行号，笔记一编辑就对不上。真正能半年后还核得住的只有**原话**。
2. **升级是不可逆点**。P1-10b 把临时卡升级成真卡，是「同一堆句子从「未确认」接到「已确认」」。如果那时候还没有出处，升级后的卡永远答不出「这条判断最初是从哪句话来的」——源笔记可能已经删了、改了。
3. **补不回来的东西要先写**。这不是「以后加个字段」，是「这一次不写就没有」。

所以 P1-12 排在 P1-10b 前面。它不动界面、不动卡的格式，只做一件事：**造卡那一刻，把出处一起落盘。**

## 做法：旁挂，不改卡的格式

出处是**每一条判断**一份，而卡的 frontmatter 是**整卡**一份的 `BTreeMap<String, String>`，装不下逐条出处。硬塞就要改卡的 Markdown 格式——那要动 `parse`/`validate`/`reanchor`、18 条对齐测试和两个逐字节对齐的 fixture。为一个还没定型的字段付这个价，不值。

改用一个按锚点键的旁挂文件：

```
仓库/vault
├── Notes/灵魂卡.md                                  ← 卡本身，一字未改
└── .litmus/soul-sources/Notes%2F灵魂卡.json          ← 出处旁挂
```

**为什么落在这里**，三条都是查过的：

- 放 `Notes/` 里会被 `kernel-store::list_non_doc_files` 当成「非文档文件」扫出来（它遍历 `notes_dir`，收任意扩展名），用户的笔记列表里会多出一个垃圾文件；
- `.litmus/local/` 已被 git 忽略（`kernel-deploy` 会写进 `.gitignore`），而出处是**用户数据**，必须跟着版本库走，不能只当本机状态；
- `.litmus/soul-sources/` 既不在 `notes_dir` 下（扫描器看不见），也不属于 `kernel-deploy` 写的那三条忽略项
  （它只忽略 `.litmus/local/`、`.thirdc/`、`.DS_Store`）。

**2026-11-24 更正。** 初版这里写的是「不在忽略名单里（会被提交）」，那是错的。核对了这台机器的库：
它自己的 `.gitignore` 第 2 行是 `.litmus/`——**整目录**，所以在这个库里旁挂不会进 git。
产品侧的备份会带上 `.litmus/`（只排除 `machine.toml`、备份签名密钥与 `backups/`），
所以换机恢复拿得回来；纯 git clone 拿不回来。要让旁挂进 git，得把那条规则改成 `.litmus/*`
再放行 `.litmus/soul-sources/`——那是改用户的库规则，不在这一条里顺手做。

我把这条错写在这里而不是悄悄改掉，因为「数据到底有没有进版本库」是这个任务唯一要保证的事，
理由错了等于保证不成立。

路径转义只动 `%` 和 `/`：可逆、不撞名、中文保持可读。撞名等于两条判断共用一份出处——正是这一层要防的那类静默错误。

## 格式

```json
{
  "version": 1,
  "card": "Notes/灵魂卡.md",
  "anchors": {
    "belief-1": {
      "source": "interview",
      "ref": "answer:belief",
      "quote": "知识不是收藏，是被用过的判断。好作品先有观点。"
    }
  }
}
```

- 键是块锚点。锚点稳定（P1-01 第一条不变量），所以 P1-10b 的「升级后锚点是超集」天然让旁挂继续对得上——升级不用懂出处。
- `quote` 存**原话全文**，不存卡片上的那句。判定用的是「原话覆盖条目正文」（与 P1-02 的 `assertGrounded` 同一条规则），所以改字、删标点、加空白都还核得住；真换了意思才报错。
- 键按锚点排序后写出，同一份内容两次序列化逐字节相同，版本库里不会抖出假 diff。

## 判定：四条，全部显式报

| code | 什么时候 | 为什么不静默处理 |
|---|---|---|
| `missing-source` | 卡里有锚点、旁挂里没有 | 补一个空出处等于伪造；这条判断就是答不出来 |
| `dangling-source` | 旁挂里有锚点、卡里没有 | 静默删掉会把「原来那句是什么」一起删了 |
| `unquoted-source` | quote 不再覆盖条目正文 | 有人改了判断却没改出处，这是最该被看见的一种漂 |
| `unmapped`（只在造卡时） | 一个区块里有多条判断，却只有一条区块级出处 | 说不清是哪一条，就报出来，不随机挂到第一条 |

## 两边怎么分

| 层 | 位置 | 条数 |
|---|---|---|
| Rust 纯逻辑（解析 / 序列化 / 三条判定） | `kernel/crates/kernel-soul/src/sources.rs` | 9 条测试 |
| Node 参考实现（同样的判定 + 落盘 + 出处→锚点映射） | `docs/spec/r2/reference/p1-12-provenance/` | 12 条测试 |

9 条是两边同名同断言的共有项。Node 多出来的 3 条**只在 Node 侧**，原因写在明面上：

1. 造卡时卡与旁挂一起落盘（要写文件）；
2. 读不到旁挂时明说读不到，不拿空表冒充（要读文件）；
3. 一个区块里有多条时，区块级出处不硬挂到第一条（这是「候选 → 锚点」的映射，纯属造卡那一步的职责）。

`kernel-soul` 是零 IO 的（`sources.rs` 只做解析、序列化、比对），所以前两条它测不了——不是漏了，是分工。产品侧的落盘随 P1-10b 的端点走 `kernel-store`。

## 还没做

- **产品侧落盘**：Rust 层有模型，没有写盘。写盘归 fs 层，随 P1-10b 的读卡/写卡/升级端点落地时接上。
- **快捕入口**：P1-02 只做了访谈 / 提炼 / 粘贴三个入口。P0-06 的 Mac 快捕还没造过灵魂卡，所以 `source: "quickcapture"` 目前只是个允许的取值，没有真实生产者。
- **已有卡不回填**：P1-12 之前造的卡没有旁挂，也不会去猜。它们的出处是**已经丢了**，回填只会造出看起来有、实际是推出来的假出处。这类卡在界面上应该显示成「这条没有出处」的常态，不是报错。

## 新思路

1. **产品**：P1-10b 的界面要能显示「这条判断没有出处」。上线那天，所有老卡都会是 16 条 `missing-source` —— 如果界面把它渲染成红色错误，用户会以为卡坏了。它其实是历史事实：这些判断当初确实没记出处。**空态和错态要分开画。**
2. **实现**：`quote` 存原话以后，卡背可以显示「你当时是这么说的」——这句原话比 ref 更有用，因为它自带上下文，用户一眼能认出是自己哪句话。
3. **计划哪里错了**：我把 P1-12 一开始想成「往 frontmatter 加几个字段」，查完 `SoulDoc` 才发现 frontmatter 是整卡一份的字符串表，装不下逐条。**先看数据结构再定方案，能省掉一轮返工。**

## 2026-11-24 追加：改写过的条目（P1-13）

P1-02 允许「改写」：用户可以改几个字再落盘。改写后正文不再是原句，但出处仍然指原话。
旁挂为此多了一个可选字段：

| 字段 | 何时出现 | 含义 |
|---|---|---|
| `edited` | 只在改写过的条目上，值 `true` | 正文是用户改的；`quote` 仍是原话 |

`check_sources` 对 `edited: true` 的条目**跳过逐字覆盖检查**，其余三条判定照旧（缺出处 / 悬空 / 锚点对得上）。
理由：改写是用户显式做的，不是程序编的；把 `quote` 换成改写后的句子，才是真的丢出处。

旧数据没有这个字段，照旧按逐字覆盖判——向后兼容，旁挂版本仍是 1。

产品的改写路径见 P1-13：`assemble` 对 `Decision::Edited` 置位，落盘后 `GET` 不报 `unquoted-source`，但旁挂里 `quote` 仍是用户原话。
