## 二、被现实推翻的假设（这一节是本轮最重要的产出）

1. **「绿纸」不是绿的。**
   从 `/Applications/Litmus.app` 里实测到的 tokens 是 `--paper-c: .972 .006 286`——冷灰偏紫的纸，色相 286。规划 §5.5 写"内容仍是绿纸"。
   **证据**：`strings` 提取的内嵌 `tokens.css` 两处定义一致。
   **含义**：要么"绿纸"指某个我没看到的主题，要么文案和实现已经分叉。**在确认之前，所有对比度都算在一个可能错的底色上。**

2. **「复用 write-result」——这个端点大概率不存在。**
   规划 §3.3 说复用 `abShow` / `chat` / `agent/apply` / `write-result`。实测路由表里有 `/agent/apply`、`/chat`、`/chat/stream`、`/publish/site`、`/search/hybrid`、`/field/place` 等，**没有 `write-result`**。
   **含义**：P1-04 的"复用现有链路"不能照抄，必须先列一份端点核实清单，否则会按一个不存在的接口做设计。

3. **「五色直接用」不成立。**
   琥珀 `oklch(.66 .14 75)` 上纸 2.93:1，低于 UI 组件 3:1。压到 `(.62 .15 72)` 才 3.44:1。
   **含义**：颜色进 tokens 之前必须过对比度脚本；这条已经变成 P1-06 的 DoD。

4. **「先列事件，再算指标」会生产孤儿。**
   16 个事件里 8 个没有任何指标消费。"我想知道"和"我要用它做决定"是两件事。
   **含义**：下一轮埋点改成指标 → 事件 → 字段的单向生成。

5. **「10 分钟访谈」零缓冲。**
   六问相加正好 600 秒，没有开场、没有确认、没有"改一个词"。真实排期应 15 分钟。
   **含义**：对外仍可承诺 10 分钟，但内部验收按 15 分钟；否则每次试跑都判失败。

6. **「200ms 快捕」的敌人不是视图。**
   原型把视图预热了，真正会掉帧的是激活与中文输入法。规划把它当成一个渲染性能问题。
   **含义**：P1-03 的验收要写"首次呼出（含输入法）P95"，不能只测二次呼出。

### 第二步：外部求证（四类来源，都要能点开）

| 类 | 要证什么 | 判定标准 |

| 竞品实际能力 | Obsidian / Heptabase / NotebookLM / ChatGPT memory 现在到底能做什么 | 必须点到具体功能页或版本说明，不接受"听说" |
