# 鹿蕊 · 执行看板

> 这份文件只回答三件事：**现在做哪一条**、**它怎么算做完**、**做完之后新长出了什么想法**。
> 规划原文不动。所有"改规划"的动作都另开一份文件，并在这里留一行。
>
> **同步方向：单向，只从本仓库同步到笔记库的镜像（2026-11-24 用户确认）。** 每条 P1 完成时批量同步一次，
> 不要边做边双向改——两边都改就等于两边都不是正本。库里要给意见，写成一份新文件带回来，不直接改镜像。

## 一、这个 loop 怎么转

三层，三种节奏，不要混在一起。

| 环 | 频率 | 做什么 | 产出 | 谁拍板 |
|---|---|---|---|---|
| **L1 · 单条 TODO** | 每一条 | 读对应章节 → 做出可跑/可看的东西 → 一条命令验证 → 写 3–5 条新思路 | 该 TODO 文档 + `Work/litmus-r2/` 产物 | 我 |
| **L2 · 阶段复盘** | 每个 Phase 结束 | 拿真实数字对账、列出**被推翻的假设**、只修订下一阶段 TODO，不重做产品规划 | `9x-复盘` 文件 | 我 + 报给你 |
| **L3 · 全面重规划** | 全部 Phase 做完 | 总复盘 → **调研你的意见** → 外部广泛求证（可点来源）→ 新规划 R2 | 新规划文件 | **你** |

**回到 L1 的条件**：L3 的新规划被确认。这就是 loop 闭合的地方。

### 三条门禁（不满足就不算完成）

1. **没有绿，不进下一条。** 每条 TODO 的验证命令必须真的跑过，输出贴在文档里。不许写"应该可以"。
2. **没有新思路，也不算完成。** 每条至少 3 条：一条关于产品、一条关于实现、一条关于"计划本身哪里错了"。
3. **没测就写"未测"。** 基线数字、性能、对比度——没有真实测量就留空并写明怎么测，不编。

### 反自欺条款（针对这个项目最容易犯的错）

- 仪表盘上出现的每个数字，必须能追到一条真实事件；追不到就删掉这个数字。
- 每份复盘必须至少列出一条**被现实推翻**的假设。列不出来，说明这一轮没测任何东西。
- 任何"已完成"的界面/交互，必须有一张截图或一段可跑的产物；只有文字描述的一律算"未做"。
