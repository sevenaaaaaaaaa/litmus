# P1-06 · 显色状态设计系统 v1

## 目标

> 五态 × 明暗 × soft/ink；对比度自动测；色盲模拟下仍可辨（靠文字+图标）。

**DoD 修订（2026-11-24，用户确认）**：原句“色盲模拟下仍可辨（靠文字+图标）”里，文字+图标是兜底，不是色觉方案。改为两条可测的：

1. 灰度/去色后，五态仍能按明度单调排序（种子最浅 → 已发布最深）。
2. 红绿色盲模拟后，相邻两态仍可区分（OKLab ΔE ≥ 0.05），且每态对纸面 ≥3:1。

“颜色不是唯一信道”仍由 card-state.mjs 的 assertAccessible 守：每态必须有 label + icon + action。

## 做了什么

| 文件 | 改动 |
|---|---|
| server/web/tokens.css | 五态 × 明暗 × 三档（fill / soft / ink），共 30 个 token；全部 oklch，零 hex |
| server/tests/palette.rs | 新增 4 条契约测试：两主题都存在、对比阶梯、ink 压 soft ≥4.5、CVD 下相邻可辨 |
| docs/spec/design-system.md | 新增「显色五态」一节，写明与语义四色不混用 |

**与 P0-05 的关系**：直接采用 P0-05 的色相与 soft/ink 结构，不另起一套（05-card-anatomy 的“对后续影响”明确要求）。唯一实质改动是把 P0-05 自己指出的“五色同明度带”改成阶梯。

## 五态

| 状态 | token 后缀 | 含义 | 主动作 |
|---|---|---|---|
| 种子 | --state-seed | 刚落下，还没有可点回的来源 | 找证据 |
| 有据 | --state-grounded | 至少有一条可点回的来源 | 找反例 |
| 有张力 | --state-tension | 与另一条证据或判断冲突，尚未决定 | 做决定 |
| 已定 | --state-settled | 用户确认过，暂时稳定 | 成稿 |
| 已发布 | --state-shipped | 已经作为页面或作品发出去 | 回流 / 更新 |

每态三档：

- fill（--state-<x>）：2px 边、图标、状态点；
- soft（--state-<x>-soft）：浅底，alpha .12（亮）/ .16（暗）；
- ink（--state-<x>-ink）：**只允许压在 soft 底上**的文字与图标。

## 对比度实测（真实数字）

脚本按 tokens.css 的 oklch 值换算 sRGB 再算 WCAG 比值；light 的底是 --bg-1，ink 的底是 soft 合成在 --surface-3 上；dark 的底是 --bg-1，ink 合成在 --surface-1 上。

| 状态 | 亮·边对纸 | 亮·ink 对 soft | 暗·边对纸 | 暗·ink 对 soft |
|---|---|---|---|---|
| 种子 | 3.29 | 5.77 | 3.95 | **4.71** |
| 有据 | 4.00 | 6.96 | 5.67 | 5.15 |
| 有张力 | 5.54 | 9.34 | 6.73 | 5.88 |
| 已定 | 6.06 | 10.02 | 8.25 | 6.64 |
| 已发布 | 7.27 | 11.24 | 10.71 | 8.13 |

- 边：全部 ≥3:1（非文本 UI 下限），且按种子 → 已发布递增。
- ink：全部 ≥4.5:1（WCAG AA 正文）。最紧的一格是暗色种子 4.71，只比下限高 0.21——所以 ink 不许直接放纸上。
- 亮色“有张力”从 P0-05 的 3.44 提到 5.54：不是换色相，是把明度压深一档，让它进入阶梯。

## 灰度与色盲

- **灰度**：对比度只依赖相对亮度，上面的递增就是灰度可读性的证明。light 3.29 < 4.00 < 5.54 < 6.06 < 7.27；dark 3.95 < 5.67 < 6.73 < 8.25 < 10.71。
- **色盲**：用 Machado et al. 2009（severity 1.0）的 protanopia / deuteranopia 矩阵模拟后，相邻两态 OKLab ΔE ≥ 0.05，且每态对模拟后的纸面 ≥3:1。红绿色盲保留蓝黄轴，所以不要求亮度顺序不变；要求的是“还分得开”。
- **文字+图标**：颜色是第三信道。card-state.mjs 的 assertAccessible 在 Node 测试里守住 label/icon/action 三件。

## 一条命令

    cargo test -p litmus-server --test palette

结果：**9 passed; 0 failed**（原有 5 条 + 新增 4 条）。

新增的 4 条：

1. five_state_tokens_exist_in_both_themes——两主题各 15 个 token 都在，暗色漏写会静默沿用亮色值。
2. five_state_edges_form_a_contrast_ladder——≥3:1 且逐态递增，相邻差 >0.15。
3. five_state_inks_pass_wcag_aa_on_their_soft_beds——亮/暗 × 双强调色四种组合，≥4.5:1。
4. five_state_states_stay_distinguishable_under_cvd——protan/deutan 下相邻 ΔE ≥0.05，且不糊进背景。

## 没做的

- 五态还没有进 field.html 的任何一屏；等 P1-10 的临时卡/真卡状态行第一次真实使用。
- 色盲模拟只覆盖 protan / deutan，没有 tritan（蓝黄色盲，人群比例低两个数量级）。
- 只测了 sRGB 数值，没有测真实屏幕色偏、没有测打印。

## 新思路

1. **产品：明度阶梯会挤压“有张力”的警示感。** 琥珀压到 L .50 后不再抢眼。解法不是把颜色调亮，而是把张力放在位置与文字上——卡背第一行必须是“冲突对象 + 一句 diff”，正面只放“⚑ 与《…》冲突”。这条直接进 P1-10 的升级前提示。
2. **实现：ink 是“坐 soft 底”的专用色，不是通用文字色。** 最紧的一格只比 4.5 高 0.21；一旦有人把 ink 直接放纸上，暗色种子会掉到 4.5 以下。CSS 里已写注释，但没有机器约束——下次可以加一条 palette 测试：扫描 field.html，禁止 state-*-ink 出现在没有 soft 底的规则里（需要解析选择器，成本不低，先记着）。
3. **计划：DoD 要先问“这条谁来测”。** 原句“色盲模拟下仍可辨（靠文字+图标）”把两件不同的事塞进一条：颜色可测的部分（阶梯、ΔE）和 UI 可测的部分（label/icon）。拆开之后，两边都能写测试。以后写 DoD 先问这一句。
