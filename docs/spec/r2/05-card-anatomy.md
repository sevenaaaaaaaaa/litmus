# P0-05 · 卡解剖 v1

## 目标

> 卡解剖 v1：正面 / 背面 / 状态边（只读）。验收：任一截图 3 秒内能回答「我在哪、这张卡是什么状态、下一步是什么」。

## 做了什么

**能双击打开的原型**：[index.html](reference/p0-05-card/index.html)（先跑一次 `node build.mjs` 生成 `dist/prototype.js`，或直接跑 `tests/run.sh`）

| 部分 | 实现 |
|---|---|
| 正面 | 标题（claim）、两行 gist、来源/反例/相关 chips、状态行（图标+文字+含义）、张力提示、下一步、meta |
| 背面（Space） | 来源（可点回）、关系、历史、**读了灵魂卡的哪几条**、四个操作 |
| 显色边 | 2px 左侧竖条，按证据覆盖度自下而上填充；不是进度条，不显示百分比 |
| 五态 | 种子 / 有据 / 有张力 / 已定 / 已发布，各有主动作与"下一步一句话" |
| 键盘 | Space 翻开、⌘↩ 推进、⌘⇧↩ 连到、⌘⇧P 发布、Esc 退回、1–5 直接切状态 |
| 无障碍实验 | 「只靠颜色」开关：把文字与图标藏起来，让 3 秒自检当场失败——用来给设计伙伴看"为什么不能只靠颜色" |

**状态机是唯一真相**：[card-state.mjs](reference/p0-05-card/card-state.mjs)，UI 只消费它。8 条测试覆盖：五态都有文字/图标/主动作、覆盖度单调、主路径、无来源不许发布、未决定不许发布、已发布可退回、未知状态/事件报错、3 秒三问。

## 对比度实测（不是估计）

用 `contrast.mjs` 把 oklch 换算成 sRGB 再算 WCAG 比值：

| 状态 | 边色 | 边上纸 | 文字色 | 字上纸 | 判定 |
|---|---|---|---|---|---|
| 种子 | #85858d | 3.36 | #4c4c55 | 7.82 | 达标 |
| 有据 | #3d865a | 4.09 | #1e5a38 | 7.48 | 达标 |
| 有张力 | #bc7400 | **3.44** | #824700 | 6.78 | 达标（调过一次，见下） |
| 已定 | #1565d7 | 5.01 | #054eb1 | 7.05 | 达标 |
| 已发布 | #005c41 | 7.42 | #004a32 | 9.57 | 达标 |

**发现并修掉的一个真问题**：琥珀最初是 `oklch(.66 .14 75)`，上纸只有 **2.93:1**，低于 UI 组件 3:1 的下限——在明亮背景下"有张力"这条边会糊掉。压到 `oklch(.62 .15 72)` 后 3.44:1，暗色版 9.2:1。这就是"把对比度写进测试"的价值：靠眼睛看不出来。

## 新思路

1. **五色不是问题，"五色同明度带"才是问题。** 五种状态在灰度下几乎一样亮。现在的解法是文字+图标（已做）；下一步应该给明度阶梯（种子最浅、已发布最深），让灰度/色盲也能读。
2. **显色边的"填充比例"是个假连续量。** 62% 没有任何含义，用户会以为能量化"证据充分度"。建议离散成 5 档（0/25/50/75/100），并且只在状态变化时动画，不常驻百分比。
3. **"有张力"不给地址等于报警不给门牌。** 光说"有张力"用户不知道跟谁冲突。卡背第一行必须是**冲突对象 + 一句 diff**，正面只放"⚑ 与《…》冲突"。
4. **卡背的"读了灵魂卡的哪几条"是灵魂卡唯一的日常露出。** 它必须可点回锚点，这要求块锚点在编辑时稳定（改一个字不能换锚点）——这条直接决定 P1-01 的数据模型。
5. **3 秒自检应该做成产品内功能。** 导出 PNG + 三问答案，设计伙伴远程也能做，不用开会。现在是一个按钮，应该变成"截图测试"的标准流程。

## 对后续的影响

- P1-01 灵魂卡解析器要与"块锚点稳定"一起设计（见新思路 4）。
- P1-06 设计系统直接采用本文件的 tokens 与对比度脚本，不另起一套。
- P1-03 五动作的键位以本原型为准。
