# Litmus Studio：桌面客户端独占能力规划

> 目标：让桌面客户端不是「浏览器套壳」，而是**本机 AI 知识工作台**——
> 能吃下本机全部内容、能用本机算力、能做浏览器做不了的事。
> 浏览器端的定位是「随处可用的轻客户端」；桌面端是「主力生产环境」。

## 0. 为什么需要桌面端（差异化判据）

| 能力 | 浏览器（线上） | 桌面客户端 | 判据 |
|---|---|---|---|
| 读任意本地目录 | ❌ 只能手动选文件 | ✅ 全盘索引 | 浏览器沙箱 |
| 批量导入/转码 | ❌ 单文件 | ✅ 后台队列 | 需要原生进程 |
| 本地小模型推理 | ❌ | ✅ Ollama/llama.cpp | 需要 GPU/CPU 原生 |
| 本地向量嵌入 | ❌（走云端） | ✅ ONNX 本地 | 隐私 + 零延迟 |
| 内嵌终端 | ❌ | ✅ PTY | 需要进程控制 |
| 全局快捷键/剪贴板/OCR | ❌ 受限 | ✅ 系统集成 | 需要原生 API |
| Git 自动提交/分支 | ⚠️ 手动 | ✅ 自动快照 | 需要常驻进程 |
| 离线可用 | ⚠️ 缓存外壳 | ✅ 全功能 | 数据在本机 |
| 拖拽 Finder → 导入 | ⚠️ 单文件 | ✅ 目录树 | 需要原生拖拽 |

**结论：桌面端的价值 = 本机算力 + 本机数据 + 系统集成。**
如果只是把网页塞进 webview，那确实没有开发意义。因此客户端必须：
1. **主动占用本机资源**（后台索引、嵌入、转码、模型常驻），把「闲着的电脑」变成「越用越聪明的知识库」。
2. **提供独占能力**，且这些能力**在浏览器端点不到**（后端用 `desktop_mode` 门禁隔离）。

## 1. 性能预算（面向主流配置）

主流笔电基线：**8 核 CPU / 16GB 内存 / 512GB SSD**（Apple M 系列或同级 x86）。
桌面端允许的常驻开销上限：

| 资源 | 空闲 | 索引中（峰值） | 说明 |
|---|---|---|---|
| CPU | < 2% | 60%（可配 20~100%） | 后台索引/嵌入分片，按电池状态降级 |
| 内存 | < 300MB | < 1.5GB | 内核 + HNSW 向量索引 + 模型句柄 |
| 磁盘 | 索引 ≈ 库体积 15% | — | FTS5 + 向量 + 缩略图 |
| 网络 | 0 | — | 默认纯本地，仅同步/发布时出网 |

**分级策略（`desktop.power` 配置）**
- `battery`（默认）：只在插电且闲置时跑重活；CPU 上限 25%。
- `balanced`：插电常开后台索引；CPU 上限 50%。
- `performance`：不限；并行转码 + 模型预热 + 全量向量索引。

## 2. 独占能力分层（T1→T4，按优先级）

### T1 · 本机内容统一入口（立刻做）
- **任意目录索引**：选一个根目录（`~/Documents`、`~/Knowledge`、外接盘），递归纳入库，不进内存只建索引；文件保持原地（in-place），不做拷贝。
- **后台转码队列**：`docx/pptx/xlsx/pdf/epub/rtf/html` → Markdown，落地到库内 `Imported/`，保留来源路径与 mtime；支持 OCR（图片 → 文本）。
- **Finder 拖拽**：拖文件/目录到窗口即入队；目录展开递归。
- **导入去重**：按 内容哈希 + 来源路径 双键，重复导入幂等。
- **本机能力面板**：展示磁盘/库体积/索引状态/队列进度/本机模型可用性。

### T2 · 本地算力（差异化核心）
- **本地嵌入**：`fastembed`/ONNX（`bge-small-zh`）→ 语义检索全离线，RAG 不出网。
- **本地小模型**：探测本机 Ollama / llama.cpp / MLX，列出可用模型，允许把「总结/打标签/问答」路由到本地模型（`local` 通道），敏感库强制 local-only。
- **私密 agent 模式**：一个库级开关 `privacy=local`，禁用一切出网工具（web 搜索、云模型、云嵌入），agent 只在本机活动。
- **模型常驻**：预热句柄，首 token 延迟 < 500ms；空闲 10 分钟卸载释放内存。

### T3 · 客户端内部命令行（power user）
- **内嵌终端**：PTY（`portable-pty`）+ xterm.js，直接跑 `litmus ...` 与 shell，工作目录自动设为当前库。
- **命令面板即 CLI**：⌘K 支持 `> ` 前缀输入任意 whitelist 命令，结果内联展示。
- **脚本化**：`.litmus/local/tasks/*.sh` 注册为可点按钮；agent 可调用（带权限确认）。
- **受限白名单**：默认只放 `litmus` 子命令 + 只读 shell（`ls/grep/rg/find/git status`）；危险命令需显式授权。

### T4 · 系统集成（长期）
- 全局快捷键（⌥Space 快速记录）、系统托盘/menubar、剪贴板历史、屏幕 OCR、分享扩展、自动 Git 快照（每 N 分钟/每次编辑）、原生通知。

## 3. 架构约束

- **门禁隔离**：所有本机操作挂在 `/desktop/*`，仅当 `state.desktop == true`（桌面壳启动时设 `LITMUS_DESKTOP=1`）才注册路由。线上部署拿不到这些端点。
- **库即真相**：任何导入/转码的产物都落盘为普通文件，可被 Obsidian/VSCode/git 直接读写，无私有格式、无锁。
- **可关可调**：每个后台任务都能在设置里单独关；有全局「省电模式」。
- **失败可诊断**：队列任务失败写入 `.litmus/local/queue.log`，UI 可见原因与重试。
- **浏览器降级**：UI 用 `/desktop/info` 探测能力，缺能力时按钮隐藏而非报错。

### 3.1 远端拉取：结构先行、正文后台

首次登录同步**不做全量阻塞**，分两段：

1. **同步阶段（亚秒级）**：本机侧登录远端 → 拉 `/docs` 列表 → 建好目录骨架 →
   `POST /desktop/pull` 立刻返回 `{total, folders, server, user}`；前端马上收起登录浮层、进编辑区。
2. **后台阶段**：`tokio::spawn` 并发 8 拉正文（浅层优先、内容相同跳过、单个失败重试一次），
   每 300 篇合入一次索引；进度由 `GET /desktop/pull/status` 轮询。

- 进度落在状态栏（`#sb-sync`），**不打断**用户操作；完成后提示「打开看看」，可点刷新。
- 失败可诊断：登录/列表失败在**同步阶段**立刻返回 4xx/5xx 与原因（不再等全量超时）；
  单篇失败计入 `failed`，不阻断其余文件。
- 账号/服务器落盘 `.litmus/local/remote.json`；页面刷新后 `resumeSync()` 接续未完成任务。
- **近期更新**：Onboarding 浮层内容由经典壳 `index.html` 的 `WHATS_NEW` 数组驱动（0.14 起经典壳退役，版本说明以 CHANGELOG 为准），
  发版时追加一条（与 `docs/RELEASE.md` 的发布清单同步）。

## 5. 转码：面向 agent 的 AI 原生表示（不是通用 MD）

**前提**：docx/pdf/epub → Markdown 已经很成熟，第三方工具一堆。Litmus 的转码价值不在「变成文字」，
而在**变成 agent 能直接结构化使用的东西**。

库内的 AI 原生表示是 `kernel-md::DocModel`（`Notes/` 下 md 与 html 并存，md 是它的确定性序列化）：

```
DocModel {
  title: Option<String>,
  blocks: Vec<Block>,                       // 有序语义块：标题/列表/代码/表格/图注/引用/脚注
  meta:  BTreeMap<String,String>,           // OKF：机器可读元数据层
  anchors: Vec<Option<String>>,             // 每块的稳定 ID（块引用 + CRDT 的根）
}
```

因此转码流水线的目标产物 = **OKF-DocModel**，而不是一份扁平 md。四件通用 md 不会做的事：

| 维度 | 通用 md 转换 | Litmus AI 原生转码 |
|---|---|---|
| 结构 | 拍平成 `#`/`-` | 保留 Block 语义（表格仍是表格对象、图注绑定图、脚注成对） |
| 溯源 | 无 | `meta` 写入 source_path / sha256 / mtime / extractor+版本 / 页码范围 |
| 可引用 | 无 | 每块生成稳定 `anchors`，agent 可精确引用某块、CRDT 可合并 |
| 可检索 | 纯文本 | 生成 outline + 摘要 + 实体/主题标签块，向量按块嵌入 |
| 资产 | 丢图 | 图片落 `Assets/`，表格转结构化，公式转 LaTeX 块 |

**元数据契约（`meta`，OKF）**：`source`、`source_sha256`、`source_mtime`、`extractor`、
`extractor_ver`、`extracted_at`、`page_range`、`lang`、`confidence`。
这套键同时是去重（sha256）与去噪（mtime/来源血缘）的地基。

**实现分工**：抽取（重、可外挂）与结构化（轻、必自研）分离。
- 抽取层：`pdftotext`/`pandoc`/`libreoffice --headless`/`tesseract` 等外部程序，或 Rust crate；产出「带版式的中间文本」。
- 结构化层（Litmus 内核）：中间文本 → DocModel（分块、语义识别、锚点、meta、资产抽取、outline/摘要）。

## 6. 去重与去噪（最严苛标准，可逆）

在「导入去重」之上加一层**主动清理**：用严苛标准找出**已经没用的文档**，默认只**隔离不删除**。

**去重（幂等）**：双键 `source_sha256` + `source_path`；同来源同内容直接跳过；同内容异来源只留一份并记 alias。

**去噪信号（命中≥阈值 → 进候选清单，逐条给出理由）**：
- 空/近空：正文 token 低于最小值。
- 样板：导航/页脚/cookie/目录页占比过高。
- 精确重复：规范化内容 sha256 相同。
- 近重复：shingle Jaccard / simhash 超阈值（保留信息量更高的一份）。
- 孤儿 + 陈旧：零入链且长期未修改、未被任何视图/发布引用。
- 被取代：同 `source_path` 血缘里有更新版本，旧版标记 superseded。
- 低信息：高噪声/OCR 乱码（字符熵异常、词典命中率低）。

**动作**：输出 `去噪报告`（路径 + 命中信号 + 建议），一键把候选移入 `.litmus/local/quarantine/`（可还原），
从索引中摘除。**绝不自动硬删**；默认只报告，用户确认才隔离。

## 7. 客户端内部脚本与终端

- 内嵌终端（xterm.js + PTY）：跑 `litmus` 与白名单只读 shell，cwd=库根。
- 脚本任务：`.litmus/local/tasks/*.sh` 注册为可点按钮；agent 可调用（危险步骤需确认）。
- Git：**待定**——取决于 Litmus 是否定位为开发工具；暂只读（`status/log/diff`），不做自动提交。

## 8. 本地模型的范围（收敛）

本地模型**不做**面向用户的「本地大模型工具/模型广场」。只为 **agent 自身**的有限能力服务：

| 用途 | 说明 |
|---|---|
| 分析 | 摘要、分类、实体/主题抽取、元数据补全、去噪判定 |
| 自动化 | 根据库状态决定下一步动作、生成/执行脚本任务 |
| 语音 | 本地 ASR（录音→文字，替代 Web Speech 的云端依赖） |

形态：探测器发现本机 Ollama/llama.cpp/MLX → 作为**内部能力**注册（`/internal/agent/*`），
不暴露模型选择器。敏感库可开 `privacy=local`，强制所有分析/自动化走本机、禁出网。
嵌入优先本地 ONNX（`bge-small-zh`），RAG 全离线。

**收益**：agent 的运行只依赖「小模型 + 本地嵌入 + 外部抽取器」，不背大模型推理的包袱，稳定且私密。

## 9. 与线上版本的关系

- 同一套内核（`kernel-*`），同一套前端（`server/web`），桌面只是**多了能力与门禁**。
- 用户在桌面端建立的库，可直接 `git push` 到自己的远端，用线上 `kb.nownexts.com` 只读浏览/分享。
- 线上端永不暴露 `/desktop/*`；桌面端可连线上 API 做同步（可选，默认关闭）。


## 10. macOS 原生层（2026-10-22）

目标：桌面端不是「套壳网页」，而是**以原生为主**的 macOS 应用。网页仍然负责内容与画布，
但应用级行为交给 AppKit。

### 主菜单（NSMenu）

| 菜单 | 内容 |
|---|---|
| 鹿蕊 Litmus | 关于（原生 About 面板）· 检查更新 · 设置… ⌘, · 服务 · 隐藏/隐藏其他/显示全部 · 退出 ⌘Q |
| 文件 | 新建文档 ⌘N · 新建文件夹 ⇧⌘N · 新建便利贴 · 最近的知识库（当前库打勾，切换后重建）· 在访达中显示知识库 · 关闭窗口 ⌘W |
| 编辑 | 撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选（标准 responder 动词） |
| 视图 | 搜索与命令 ⌘K · 切换侧栏 ⌘\ · 切换明暗 ⇧⌘L · 进入全屏 |
| 窗口 | 最小化 · 缩放 · 前置全部窗口 |
| 帮助 | 鹿蕊 Litmus 帮助 · 发布说明 · 报告问题 |

- 自定义项只发 `menu:*` CustomEvent 给壳，动作仍调用网页里已有的 `newDoc / openPalette / openSettings` 等函数，
  与键盘快捷键同一条路径，不做第二套实现。
- 菜单构建失败只记日志、不阻塞启动（`[menu] 已安装主菜单（N 个顶级菜单）`）。

### 窗口

- 窗口几何持久化在 `<app config>/window.json`（逻辑坐标），Resized/Moved 节流 700ms 落盘；首次启动 1440×900。
- 标题跟随当前知识库：`<库名> — 鹿蕊 Litmus`（Mission Control / 窗口菜单可见）。
- 关闭按钮仍是「隐藏到菜单栏」，⌘Q 走标准退出。

### 仍然保留的原生能力

红绿灯自定义内嵌与 56px 顶栏同一中线 · 菜单栏图标（tray）· 全局快捷键 Alt+Space 剪贴板落库 ·
原生文件夹选择（NSOpenPanel）· 原生通知 · 原生分享 · 触觉反馈 · 系统打印 · 在线更新（GitHub latest.json）。


### 侧栏材质（2026-10-22）

- 主窗口改为透明窗口（`transparent(true)` + `macOSPrivateApi`），webview 之下垫一层
  `NSVisualEffectView`（`Effect::Sidebar`，跟随窗口激活态）。
- 网页只给「内容区」上色：`#canvas` 与 `#grid` 用 `clip-path` 裁到
  `chrome-h / dock-h / rail-x` 之内，顶栏、侧栏、底栏留半透明（72% / 64% / 72% 纸色）。
- 节点与连线因此不会滑到侧栏下面；滚动/平移坐标系不变（`clip-path` 只影响绘制与命中区）。
- 材质设置失败时 Rust 给 `<html>` 加 `no-vibrancy`，整窗回落到不透明纸面，不留透明洞。

### 原生右键菜单（2026-10-22）

- 右键动作列表由网页序列化成 `{sep | label, enabled}`，经 `desktop_context_menu` 命令交给 Rust；
  Rust 用 `MenuBuilder` 生成 NSMenu 并在光标处 `popup_menu`。
- 菜单项 id = `ctx:<index>`；选择后全局菜单事件把 index 发回网页（`ctx-pick`），
  网页执行原来那一项的函数——动作仍只有一份实现。
- 浏览器版/命令失败时自动回落到原来的 HTML 菜单（`openCtxHtml`）。
