# Design Brief — 给 Claude Code 的开发简报：让 Litmus 成为工艺品

日期：2026-10-12 · 委托人：产品负责人 · 执行：Claude Code
目标：全面提升 ThirdC（鹿蕊 Litmus）的**交互、UI 设计与配色**，达到工艺品水准。

---

## 一、产品定位（一句话）

**鹿蕊 Litmus** 是一个 AI 时代的知识操作系统：以本地文件为真相（Obsidian 之长）、以模块化/数据库/画布为组织形态（Notion/Tana/Heptabase 之长）、以 AI/Agent/MCP 为连接与洞察引擎（不重走老路的差异化），最终成为一个**工艺品级好看**的个人知识与 AI 知识库管理工具。

## 三、愿景三支柱（所有设计决策的判据）

### 支柱一：本地文件即真相（Obsidian 之长，已实现，勿破坏）

- 用户可见的一切都是磁盘上普通文件（MD/HTML/JSON/.view/.tag），任何系统工具可读。
- **系统级红利要吃满**：git 版本管理、Spotlight/Everything 检索、任意编辑器协作、iCloud/NAS 同步、脚本批处理——UI 设计要"暴露"这些红利而不是遮蔽（例如显示真实路径、右键"在 Finder 中显示"、复制绝对路径）。
- 红线：任何设计不得把用户内容锁进私有存储（宪法 §1）。

### 支柱二：模块化 / Database / 画布（Notion-Tana-Heptabase 之长，部分实现）

- 已有：画布（自由布局/看板/时间线三视图）、.view 数据库视图、块级 CRDT、memo 卡片流。
- 缺口（本次任务的设计重心之一）：
  - **块级操作的丝滑感**：Notion 式拖拽手柄、/命令、块内多选——现有编辑器是 textarea，交互距离它们有代差；
  - **画布的空间感**：节点连线视觉太弱（`updateEdges` 只有细线），Heptabase 的空间推理感靠"卡片即桌面物件"的质感；
  - **database 字段化**：Tana supertags 式"标签即类型"（机制③已设计未实现）。

### 支柱三：AI native（差异化主战场，已实现协议层）

- 已有：A2UI 原生渲染（AI 界面即协议）、引用回链（答案旁必有来源卡）、MCP server（外部 agent 可读写库）、动作栏 AI 动词、agent 工具贡献。
- 设计要求：AI 能力必须**以交互呈现**而不是藏在功能列表里——来源卡要好看得像引文、动作栏要像" magic wand "而不是菜单项、Agent 对话舱要像"与同事并肩"而不是聊天窗。

### 差异化宣言（用户原话的固化）

> 不是把所有笔记应用走过的路重走一遍，而是让 AI、AI Agent、MCP 实现以前实现不了的与其他场景的连接和洞察。

任何"抄竞品"的交互，落地时都要问：**这里的 AI/Agent 能不能做得比原版更深？**（例：抄 Notion 数据库时，字段填充和视图生成应该是 agent 能代劳的；抄 Heptabase 画布时，卡片间关联应该是 AI 主动揭示的。）

## 四、本次任务：交互 / UI / 配色 工艺品化

### 4.1 配色（最高优先级——现状是"能用"，目标是"出身名门"）

- 现状：`server/web/tokens.css` 全 oklch（零 hex，底子好），但层次感不足、暗色模式偏闷、强调色单一。
- 方向：
  - 建立**完整的多层次色板**：background 两级 / surface 三级 / border 两级 / text 四级 / accent 主副 + 语义色（成功/警告/危险/信息），全部 oklch 并给出明度阶梯公式；
  - 借鉴水准：Linear 的克制暗色、Arc Browser 的温度感、Things 3 的留白比例——不是抄颜色，是抄**对比度纪律与色彩层次**；
  - 暗色模式是主场景（现有用户习惯），亮色模式同等打磨；
  - 保留鹿蕊品牌基因（Litmus 试纸的"显色见真"——accent 可考虑从单一蓝向"石蕊试纸红蓝双色渐变"演化，需给出两版对比）。
- 验收：任何一屏截图，色彩层次 ≥4 级可见；对比度全部过 WCAG AA；oklch 无 hex。

### 4.2 交互（第二大优先级——现状是"功能齐"，目标是"手感丝滑"）

- 方向（逐条可验收）：
  1. **微交互动效系统**：统一时长/缓动 token（现有 `--ease-out/--ease-spring` 扩展为家族），所有浮层/卡片/按钮有一致的 enter/exit/hover/active 反馈；动效可关（prefers-reduced-motion 已部分支持，补全）；
  2. **键盘流完整性**：⌘K/J/F 已有，补 ⌘N（新建）、方向键在画布节点间移动、Tab/Shift+Tab 焦点环样式（工艺品细节）；
  3. **空状态设计**：每个空态（画布空/检索无果/memo 空/回收站空）有一句有性格的文案 + 一个行动按钮，不许光秃秃；
  4. **加载骨架**：现有骨架屏推广到所有慢路径（memo hub、view 渲染、图表）；
  5. **拖拽手感**：节点/卡片拖拽时的抬起阴影、落点指示、对齐磁吸——画布拖拽现在是"位移"没有"物理感"。
- 验收：连续操作 10 分钟不出现一次"界面卡住不知道点哪"的状态。

### 4.3 UI 设计（第三优先级——现状是"功能化"，目标是"工艺品"）

- 方向：
  1. **信息密度分级**：Studio 画布（低密度物件感）/ 列表视图（中密度）/ 表格（高密度）三档显式设计，不允许一个样式打天下；
  2. **质感体系**：surface 用细边框+微渐变+一点内阴影的"物件感"（Heptabase 卡片物理感），浮层用 backdrop-filter 但控制模糊半径纪律（现在有 12/16/18/20px 四种，收敛为两档）；
  3. **图标纪律**：现有混用 svg/emoji/文字（🕸/⌘/⋯）——统一为一套线性图标（2px stroke，与现有 iconSvg 家族合并），emoji 全部退役或降级为装饰；
  4. **字体排印**：正文/标题/等宽三族已定，补字号阶梯（11/12.5/13.5/15/19 现状 → 明确 5 级 + 行高配对）与数字等宽处理（mtime/score 用 font-variant-numeric）；
  5. **标志性瞬间**：每个主界面需要一个"记住它"的细节——建议从 Magic 扇形（已有）、A2UI 来源卡（引文卡片化）、Memo 热力图三者深化，而不是新增元素。
- 验收：随机 5 屏截图发给 3 个没用过的人，"这个应用好看吗"平均分 ≥4/5。

### 4.4 明确不做（防跑偏）

- 不引入前端框架/构建链（vanilla 单文件是刻意架构，宪法级）；
- 不重做信息架构/模式体系（七模式已验证）；
- 不新增大功能（本 brief 只管"壳"的工艺品化；supertags 等"芯"任务另行排期）；
- 不破坏任何现有端点/文件格式/测试（30+ 组测试必须保持全绿）。

## 五、工作方式建议

1. 先通读：`docs/spec/os.md`（宪法）→ `product-principles.md`（产品原则）→ `server/web/tokens.css` → `server/web/index.html`（全量壳，约 8000 行，所有 UI 都在里面）；
2. 分四个 PR 推进，每个可独立验收：①配色体系 → ②图标与字体纪律 → ③微交互动效 → ④信息密度与标志性瞬间；
3. 每个 PR 跑通：`cargo test --workspace` 全绿 + `bash scripts/perf-check.sh` 预算内 + 真浏览器目视；
4. 提交纪律：零 hex 颜色、零新依赖、`git status` 清零、三件套（GitHub/服务器部署/桌面包）。

## 六、一句话总结（给执行者的心智模型）

**芯已经是世界级的（文件真相+AI 协议+CRDT），你只需要让壳配得上芯——像一个大师级装帧师，把一部内容极好的书做出配得上它的封面、纸张与手感。**
